# DSA Memory

A Google Chrome / Brave extension that automatically captures your accepted HackerRank submissions and saves them to a Supabase database.

## Architecture

```text
HackerRank UI
→ Content Script (DOM Observer for success states)
→ Service Worker (Deduplication + Supabase insertion)
→ Supabase
```

## Requirements

* Node.js (tested on v24)
* npm
* Supabase project
* Brave / Chrome browser

## Environment Variables

Create a `.env` file in the root of the project with your Supabase credentials:

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

## Supabase Database Setup

1. Go to your Supabase project's SQL Editor.
2. Run the migration found in `supabase/migrations/20260923000000_init.sql`.
   This will create the `problems` table and set up the necessary RLS policies for the MVP.

## Build

To compile the extension:

```bash
npm install
npm run build
```

The output will be generated in the `dist` folder.

## Install Locally

1. Open your browser and go to `chrome://extensions` (or `brave://extensions` in Brave).
2. Enable **Developer mode** (toggle in the top right).
3. Click **Load unpacked**.
4. Select the `dist` folder generated by the build step.
5. The extension should now be installed. Ensure it's enabled.

## Testing a Submission

1. Go to any problem on [HackerRank](https://www.hackerrank.com/challenges/solve-me-first/problem).
2. Ensure you are logged in.
3. Write a correct solution in the editor and click **Submit Code**.
4. The extension will automatically detect the "Congratulations!" or "Accepted" success state.
5. A green toast reading "✓ Saved to DSA Memory" will appear in the bottom-right corner.
6. Check your Supabase `problems` table to verify the record was inserted.

## Debugging

* **Popup**: Click the extension icon. It should show a "Connected to Supabase" status.
* **Content Script**: Open the HackerRank page, open DevTools (F12), and check the Console. You should see `[DSA Memory] HackerRank observer initialized.` and subsequent extraction logs.
* **Service Worker**: Go to `chrome://extensions`, find DSA Memory, and click "service worker" to inspect the background script logs.

## Known Limitations

1. **Authentication**: This MVP uses the Supabase Anon Key and an open Row-Level Security (RLS) policy for ease of testing. In production, you must implement user authentication (e.g., Supabase Auth) and update the RLS policies to enforce `auth.uid() = user_id`.
2. **HackerRank Code Extraction**: The extension currently attempts to extract the solution code directly from the Monaco editor (`.view-lines`) or submission view. Because Monaco virtualizes DOM elements and breaks text, indentation might not be perfectly preserved. A more robust (but complex) alternative would be injecting an XHR interceptor to read the raw `fetch` payload.
3. **Deduplication**: Due to the limitations of client-side extraction, external submission IDs are not perfectly exposed on the DOM. Deduplication uses a fallback heuristic: it hashes the problem URL and the code, and prevents re-submissions within a 1-hour window.
